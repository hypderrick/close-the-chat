# 使用说明

## 开始一个项目

1. 复制一份 `项目启动包` 文件夹，改名为你的项目名。
2. 用 Claude Code 或 Codex 打开这个文件夹，直接说你要做什么。

第一次打开时，Agent 会先和你一起把项目说明填好。

## 已有的项目

1. 把整个 `项目启动包` 文件夹复制到你的项目里。
2. 打开这个项目，跟 Agent 说：「按 `项目启动包/机制/改造说明.md` 改造这个项目」。

它会先提醒你备份，并自己备份规约和规则类文件到 `_改造前/`；然后给你一张方案表，你确认后它才动手。

`项目启动包` 文件夹只是临时放进去给它当模板用的，改造完它会被移进 `_改造前/`，项目里不会多出这一层。不要把里面的文件直接倒进项目根目录，否则会覆盖你原来的 `CLAUDE.md`。

## 启动包出了新版本

已经接入过的项目：

1. 把新版的整个 `项目启动包` 文件夹复制到项目里。
2. 跟 Agent 说：「按 `项目启动包/机制/升级说明.md` 升级这个项目」。

它只替换通用的部分。替换之前，它会先告诉你变了什么，等你确认。你项目自己的流程、规则、风格和进度不会被自动改动；如果新版改了规则的写法，它会列出哪些旧内容不符合新规则，你同意了才改。

## 平时：直接说需求

你只管说出需求，其余的交给 Agent：

- 它会把你定下的规则和风格记进文件，写之前先问你。
- 想知道做到哪了，问它「做到哪了」。
- 一件事做到可以验收了，你说一声就行；你没说的话，它判断差不多了也会主动问你。你确认后，它会帮你收尾：记下要沉淀的东西，问你要不要归档这个对话。

一个文件都不用你自己维护。

## 什么时候新开对话

**一件事，一个对话。**

- **继续当前对话**：还是刚才那件事，比如同一篇稿子的修改、同一个功能的调整、同一批 bug。
- **新开对话**：换了一件事，比如写新主题、做新功能、处理和刚才无关的问题。

新开对话不会丢东西：你定下的规则和进度都在文件里，新对话会自己读。

你提了另一件事时，Agent 也会提醒你，并帮你新开对话或给你一句开场话。拿不准的时候，直接问它：「这个要新开对话吗？」

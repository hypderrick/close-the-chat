# 收尾说明

给 Agent 看。用户确认这件事通过之后读，按顺序做完。

1. **沉淀检查**：列出这次对话里还没写进文件的要点，一次性问用户要不要写（写之前必须先问，不可覆盖；怎么写见 `机制/沉淀说明.md`）。
   顺带看一眼这次开工时读过的规约和 `沉淀/` 文件：明显变长、有重复、混进了日期或事件记录，或者标「每次」的文件里有一大块只对某类任务有用的内容，就在同一次提问里提议整理。只用已经读过的内容判断，不要为了检查去通读别的文件；没有问题就不提。
2. **项目自己的收尾步骤**：如果「本项目」里规定了完成后要做的事，比如把成果挪到某个文件夹，就照做。
3. **更新进度**：如果 `进度.md` 里有对应条目，整行移到 `进度-已完成.md` 的最上面，写上完成日期。
4. **归档对话**：问用户「要归档这个对话吗？」。你所在的工具能归档当前对话的，用户同意后就帮他归档；不能的，提醒用户自己归档。归档后这个对话就结束了，所以这一步一定放在最后。

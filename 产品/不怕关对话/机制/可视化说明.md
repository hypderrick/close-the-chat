# 进度看板：可视化说明

只在用户要求做可视化看板时使用。没有要求就不做，`进度.md` 本身就够用。

## 原则

- **数据只来自 `进度.md` 和 `进度-已完成.md`。** 看板只读，不另存数据，也不修改这两个文件。改状态仍然由 Agent 按 `机制/进度说明.md` 去改文件。
- **先给用户看要处理的事。** 用户打开看板，第一眼应该看到需要自己动手的东西。
- **做最小可用的版本**：一个本地 HTML 页面加一个读取文件的小脚本就够了，不要引入框架或数据库。

## 必须展示的内容

1. **要你处理**（放在最上面）：状态是「待你验收」和「需要你决定」的条目。每条显示：
   - 事项（用户原话摘要）
   - 要做什么：去哪里看、应该看到什么，或者要决定什么
   - 结果链接
2. **进行中**：状态是「已收到」和「处理中」的条目，显示事项和最后更新时间。
3. **已完成**：来自 `进度-已完成.md`，默认折叠，按完成时间倒序。
4. 顶部显示一行计数：要你处理 N 条 / 进行中 N 条 / 已完成 N 条。

如果项目还有任务队列这类执行细节（比如卡片、token 用量），可以放在条目展开以后再显示，不要放在首屏。

## 交互

- 自动刷新：每 30 秒重新读一次这两个文件，或者监听文件变化。
- 不做编辑功能。用户想改状态，就在对话里说，由 Agent 改文件。

## 风格

- 默认使用 `黑金设计规范.md`（和本文件放在同一个文件夹）。颜色、字号、间距都按里面的变量来，不要另起颜色。
- 状态和颜色的对应：
  - 待你验收 → info
  - 需要你决定 → run（金色系，最醒目）
  - 处理中 → run
  - 已完成 → ok
  - 已收到 → 中性的 muted
- 开始做之前，先问用户一句：「默认用黑金风格，要换别的风格吗？」用户要换的话，在项目的 `沉淀/风格.md` 里记下新风格，之后都按新风格来。

## 交付

- 看板文件放在项目的 `看板/` 文件夹，并在 `AGENTS.md` 的文件夹说明里登记一行。
- 告诉用户怎么打开它（打开哪个文件，或者访问哪个地址）。

# 升级说明：已接入的项目换成不怕关对话的新版

给 Agent 看。用户会把新版的整个 `不怕关对话/` 文件夹复制到项目根目录，然后说「按 `不怕关对话/机制/升级说明.md` 升级这个项目」。下面说的 `不怕关对话/` 都指这个新复制进来的文件夹。

## 升级什么，不动什么

| 内容 | 怎么处理 |
|---|---|
| `AGENTS.md` 的「工作机制」一节 | 整节替换成新版 |
| `机制/` 文件夹 | 用新版替换 |
| `AGENTS.md` 的「本项目」一节 | **不动** |
| `沉淀/`、`进度.md` | **不动**。新版改了沉淀或进度的规则时，按第 6 步提议整理，用户同意才改 |
| `CLAUDE.md` | 确认只有一行 `@AGENTS.md`，不是的话告诉用户 |
| 产出（草稿、成品、素材、代码等） | **不动** |

## 步骤

### 1. 看版本

- 读项目 `AGENTS.md` 里「工作机制」一节标题上的版本号。标题里没有版本号的，按 v1.0 处理。
- 读 `不怕关对话/AGENTS.md` 里的版本号。
- 两边一样的话，告诉用户已经是最新版，把 `不怕关对话/` 文件夹删掉，到此结束。

### 2. 告诉用户变了什么，等确认

- 对比两边「工作机制」一节的差别，用几句大白话告诉用户：新版新增了什么、改了什么、删了什么。
- 检查「本项目」一节里有没有和新版「工作机制」冲突的地方。有的话单独列出来，问用户怎么处理。按「本项目优先」的规则，冲突时默认保留「本项目」的写法；但新版里标了「不可覆盖」的条款，一律以新版为准。
- **用户确认之前，什么都不改。**

### 3. 备份

把项目现有的 `AGENTS.md`、`CLAUDE.md` 和 `机制/` 原样复制到 `_升级前/<今天日期>-<新版本号>/`（例如 `_升级前/2026-11-24-v1.3.1/`）。下面说的「备份文件夹」都指它。

**备份一律不覆盖。** 复制前先确认目标位置还没有同名文件；已经有了，就停下来告诉用户，不要盖掉。复制完核对一遍：备份里的文件和原件一样。

### 4. 替换

1. 把项目 `AGENTS.md` 里从「## 工作机制」开始一直到文件末尾的内容，换成 `不怕关对话/AGENTS.md` 里同样范围的内容，逐字复制。
2. 用 `不怕关对话/` 里的 `机制/` 替换项目里的 `机制/`。
3. 用户在第 2 步对冲突做了决定的，按决定修改「本项目」一节。改「本项目」前必须先问（不可覆盖）：第 2 步的确认就算问过了，没在第 2 步提到的地方不要改。
4. 把 `不怕关对话/` 文件夹移进备份文件夹。

### 5. 自检和汇报

- 项目 `AGENTS.md` 的「工作机制」一节和 `不怕关对话/` 里的逐字相同。
- 「本项目」一节除了用户同意改的地方，和升级前一样。
- `沉淀/`、`进度.md` 和产出都没有被改动。

告诉用户：升到了哪个版本、改了什么、备份在哪里。

### 6. 按新规则检查已有内容（新版改了沉淀或流程规则时才做）

替换完成后，新规则只管以后。已有的 `沉淀/` 和「本项目」一节可能还留着不符合新规则的内容，要单独检查一次：

1. 按新版「工作机制」和 `机制/` 里的沉淀说明、进度说明，检查 `沉淀/` 里的每个文件、`进度.md` 和「本项目」一节，列一张表：哪一条、不符合新版哪条规则、建议怎么改（提炼成原则、合并进哪一条、改成例子、删掉）。
2. 「本项目」里有和新规则冲突的规定（比如要求 Agent 维护事件记录），也列进表里。
3. 从 v1.2 或更早升上来的，表里还要加上这两项：
   - 「做事之前先读」的每一行补上什么时候读：每件事都用得上的标「每次」，只对某类任务有用的写明哪类任务。逐行给出建议，用户确认。
   - `进度.md` 里状态是「已完成」的条目，移到新建的 `进度-已完成.md`（格式照备份文件夹里的 `不怕关对话/进度-已完成.md`），并在「做事之前先读」里登记它。
   - `进度.md` 里不是「用户交代的、还没做完的事」的内容：事实和资料（如「某某已发布」）建议移到资料文件；「待观察」这类规则候选建议当场问用户写不写，不写就删；不在规定状态里的自创状态，建议改掉。
4. **用户确认之前，什么都不改**（不可覆盖）。用户可以只同意其中几条。
5. 改之前把要改的文件复制到备份文件夹里的 `第6步前/` 子文件夹，保持原来的相对路径。不要放在备份文件夹的第一层：那里的 `AGENTS.md` 是第 3 步存的升级前原件，同名会被盖掉。改完告诉用户改了哪些。

最后建议用户新开一个对话，第一句问「你读到了哪些项目规约？」，确认新版已经生效。

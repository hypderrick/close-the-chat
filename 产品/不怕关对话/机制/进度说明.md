# 进度说明

给 Agent 看。要建进度条目、改状态时读。`进度.md` 由 Agent 维护，用户不需要动手记。

## 只记什么

`进度.md` 只放**用户交代的、还没做完的事**，每次开工都要读，所以要短。

- **什么时候建条目**：用户提的事在当前回合做不完，比如交给别的 Agent 或队列执行、要等明天、或者分好几步完成，就建一条。当场就能做完的事不记。
- **一条写什么**：用用户自己的话写这件事；结果在哪里；现在等谁、等什么。只写这件事本身做到哪了。
- **不写进来的**：
  - 项目要用的事实和资料（数字、链接、某样东西已经发布了），写进项目的资料文件，比如素材库。用户在对话里顺口提到的事实，不是进度。
  - 还没定下来的规则候选（「待观察」「再碰到一次就提议」），按 `机制/沉淀说明.md` 当场问，不在这里攒。
  - 日期流水、修改记录。
- 状态只用下表这几种，不要自己发明新的。

## 在哪些节点更新（谁做这一步，谁就更新）

| 节点 | 状态改为 |
|---|---|
| 用户提出这件事，当前回合做不完 | 已收到 |
| 开始做，或者交给别的 Agent 或队列 | 处理中 |
| 做完、自查通过，可以给用户看了 | 待你验收（写清楚去哪里看、应该看到什么） |
| 卡住了，需要用户拍板或授权 | 需要你决定（写清楚要决定什么） |
| 用户说通过 | 整行移到 `进度-已完成.md` 的最上面，写上完成日期；`进度.md` 里不再留这一条 |
| 用户说不通过 | 处理中（写上原因） |

## 查询和看板

- 用户问以前做过什么、找以前的结果时，读 `进度-已完成.md`。
- 用户要可视化看板时，按 `机制/可视化说明.md` 来做。`进度.md` 和 `进度-已完成.md` 是唯一的数据来源，看板只读不写。

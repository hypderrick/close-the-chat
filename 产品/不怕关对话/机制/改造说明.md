# 改造说明：把已有项目接入不怕关对话

给 Agent 看。用户会把整个 `不怕关对话/` 文件夹复制到已有项目的根目录，然后说「按 `不怕关对话/机制/改造说明.md` 改造这个项目」。

## 原则

- **不丢东西。** 任何文件都不删除；被替换或合并掉的旧文件，原样放进 `_改造前/`。
- **不动产出。** 草稿、成品、素材、代码等工作产出保持原位，不移动、不改名。
- **先给方案，用户确认后再动手。**
- 外部有人引用的文件（技能、脚本、其他项目里写死的路径）不移动。

## 步骤

### 0. 备份（第一件事，做完再往下走）

1. **先提醒用户备份。** 告诉用户：改造会改动规约和规则类文件，建议先给整个项目做一份备份。同时说明项目的总大小，以及可以怎么备份：
   - 项目是 git 仓库：建议先提交一次。
   - 项目不是 git 仓库：可以复制整个文件夹，或者用 Time Machine 等工具备份。
2. **Agent 自己再做一份备份。** 不管用户有没有备份，都把项目里所有「非产出」的文件原样复制进 `_改造前/`，保持原来的相对路径。「非产出」包括：根目录下的文档、规约、规则、风格、配置文件，以及脚本、工具。产出类文件夹（草稿、成品、素材、代码）因为不会被改动，可以不复制。
3. 告诉用户：备份了哪些文件、放在哪里、用户自己的完整备份做了没有。用户回复「可以开始」之后，才进行下一步。

### 1. 盘点

- 读项目根目录下已有的规约文件（`CLAUDE.md`、`AGENTS.md`、`CLAUDE.local.md`、`README` 等），以及规则、风格、约定类的文档。
- 对每个打算移动的文件，搜索它的文件名在哪里被引用：项目内部，加上 `~/.claude/skills`、`~/.codex` 这类技能和配置目录。
- 列出项目里的产出类文件夹。这些只做记录，不动。

### 2. 出映射方案，给用户确认

用一张表告诉用户每样东西去哪里：

| 现有内容 | 去哪里 | 说明 |
|---|---|---|
| 规约里的项目说明、流程、文件夹说明 | `AGENTS.md` 的「本项目」 | 精简措辞，不改变意思 |
| 规约里会过期的内容（做到哪一步、最新文件名等） | `进度.md`，或者删掉 | 删掉的内容在 `_改造前/` 里有原件 |
| 规则、约束类文件 | `沉淀/规则.md`，或者整个文件移进 `沉淀/` | |
| 风格、偏好类文件 | `沉淀/风格.md`，或者整个文件移进 `沉淀/` | |
| 事件记录（修改记录、改稿日志、带日期的逐条反馈） | 不进 `沉淀/`：能提炼成规则的提炼成规则，好例子留作「反例 → 正例」，其余留在 `_改造前/` | 「工作机制」第三节规定 `沉淀/` 不写事件记录 |
| 要求 Agent 维护事件记录的规定（如「每次改稿都记一行修改记录」） | 删掉，或者改成提炼规则的做法 | 和第三节冲突，单独列出来问用户 |
| 资料类文件（素材库、背景信息等） | 留在原处，在「做事之前先读」里登记 | 它们不是沉淀 |
| 有外部引用的文件 | 留在原处，在「做事之前先读」里登记 | |
| 产出类文件夹 | 不动，在「文件夹」里各写一句用途 | |

另外单独列出：

- 内容重复或互相冲突的条目，问用户保留哪个；
- 原项目里和「工作机制」中「不可覆盖」条款冲突的做法。例如原来规定 Agent 可以直接改规则或风格文件，不用先问：要告诉用户，改造后这条一律改成先问，不能作为本项目的例外保留；
- 你拿不准的东西，问用户。

**用户确认之前，什么都不改。**

### 3. 执行

1. 核对第 0 步的备份：要改动或移动的文件都已经在 `_改造前/` 里。
2. 把 `不怕关对话/` 里的 `机制/` 复制到项目根目录。
3. 写 `AGENTS.md`：
   - 「本项目」一节按确认过的方案填写；
   - 「工作机制」一节从 `不怕关对话/` 里的 `AGENTS.md` **原样复制**，一个字都不改。
4. 把 `CLAUDE.md` 改成只有一行 `@AGENTS.md`。原来的内容已经迁进 `AGENTS.md`，原件在 `_改造前/`。
5. 按方案移动规则和风格文件。新建的 `沉淀/` 文件都要登记到「做事之前先读」。
6. 只有在已经有跨对话的事项时，才建 `进度.md`。
7. 把 `不怕关对话/` 文件夹本身移进 `_改造前/`。

### 4. 自检

- `CLAUDE.md` 只有一行 `@AGENTS.md`。
- `AGENTS.md` 的「工作机制」一节和 `不怕关对话/` 里的逐字相同。
- 原规约里的每一条规则，要么在新的地方能找到，要么是用户同意删掉的。逐条核对，一条都不能漏。
- 「做事之前先读」里登记的文件都真实存在；`沉淀/` 里的每个文件都登记了。
- 产出类文件夹没有被改动。

### 5. 汇报

告诉用户：

- 改了什么，每样东西现在在哪；
- 旧文件在 `_改造前/`，确认没问题后可以自己删掉；
- 建议新开一个对话，第一句话问：「你读到了哪些项目规约？做事之前要先读哪些文件？」能答出 `AGENTS.md` 和「做事之前先读」里的文件，就说明接入成功了。然后照常提一个需求试试。（不要用 `/memory` 当第一句：有的客户端要等会话开始后才能用它。）
